# Daemonarium

<img src="logo.svg" alt="Heptagram" width="96" height="96">

Daemonarium is a sandboxed process runtime. The guest is WebAssembly. Native hosts, and a Node host, sit beside it so a process can reach a filesystem or a database without leaving the box. Processes do not call each other. They pass messages on kernel sockets. The same contract is meant to run on Node, in the browser, and on a native WebAssembly machine, so an isomorphic application behaves the same in each place.

The point of the box is code you did not write by hand, including code generated by a model. It has to be possible to run that code, to stop it, and to see what it did, without giving it the machine.

## Isolation

A process cannot open a socket, watch another process, or touch the host except through the kernel. A shield process stands in front of the kernel, so an untrusted guest never speaks to it directly. Each process has a **mana** budget. Mana is gas: work spends it, and a process that runs out stops. That accounting is enough to drive a smart-contract engine later. It is not the product we are shipping first.

## Record, replay, debug

The kernel records a process: snapshots of its life and the I/O that happened between them. A recording debugger already replays those dumps (`.waosrec`) without bringing the kernel back up: timeline, messages, and the API the process was speaking. Post-mortem debug of generated code is a first-class goal, not a log file you grep after the fact.

## What is still being built

A real-time database and a watch protocol sit next to the recordings. The recording tells you what already happened. The watch is so you can see a living process, and the data it is writing, while it is still running. The database is observable: a table, an index, or a range can be followed as it changes.

## Pieces

Satellites land one repository at a time. The intended set:

- a C++ reflection RPC and type registry
- a clang and Emscripten toolchain that can compile that reflection to WebAssembly
- the kernel, the recorder, and the recording debugger
- a host filesystem behind the socket contract, not WASI
- a chart and rendering stack that already uses the same session machinery

[Wizards Ephemeris](https://github.com/wizards-ephemeris/wizards-ephemeris) is a separate library, under its own organization. Daemonarium links to it. It does not absorb it.
